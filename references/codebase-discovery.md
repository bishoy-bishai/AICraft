# Codebase Discovery

Before changing code, learn how the project already works.

## Sampling

Inspect representative examples rather than a single file:
- 3–5 representative modules
- 2–3 API endpoints
- 2–3 persistence models/repositories
- 3–5 tests
- relevant configuration and package conventions

## Discover

Record an internal profile for:
- naming
- file/folder structure
- module boundaries
- functions and classes
- async patterns
- types/interfaces
- error handling
- validation
- dependency injection
- API response conventions
- database access
- test organization

## Rule

Follow established conventions when they are consistent and safe.

If an existing convention creates a correctness or security problem, do not copy it. Explain the deviation.

## Consistency

New code should look like it belongs in the repository. Do not introduce a new style because it is personally preferred or fashionable.
