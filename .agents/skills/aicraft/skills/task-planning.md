# Task Planning

Use bounded tasks.

Preferred sequence when applicable:

API → Integration → E2E → Hardening

Every task should define:
- Goal
- Scope
- Acceptance Criteria
- Dependencies

Do not invent dependencies or split work into artificial micro-tasks.

A task is Ready only when the requirement, contract, dependencies, ownership, and acceptance criteria are sufficiently clear.

A task is Done only when implementation, verification, and architectural compliance are complete.
